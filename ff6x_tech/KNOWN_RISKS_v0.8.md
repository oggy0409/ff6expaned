# TECH v0.8 — known risks and limitations

R1-R20 carried over (R2, R11, R14 updated for v0.8); R21-R32 new in v0.8.

| # | Risk / limitation | Severity | Why / mitigation |
|---|---|---|---|
| R1 | **Downgrade is one-way.** A v0.7.1 save loaded in an older FF6X build or in Rev 1 shows extended items as their low-byte vanilla aliases (QA Blade13D → Chocobo Brsh, QA Mail 13E → DaVinci Brsh, QA Charm13F → Magical Brsh). | Medium (QA saves only today) | Older ROMs ignore `$1CF8-$1D27`. Do not load v0.7.1 saves in older builds. |
| R2 | A QA save loaded in the **production** ROM keeps every production item `$100-$126` (defined there too) and loses only the QA-only items `$13D-$13F` (removed, not truncated). | By design | `XSanitize` removes undefined ids; emulator stress P1 (v0.8). |
| R3 | `TAKE_EXT_ITEM` ($67) removes from the inventory only; an equipped extended item is not taken. `HAS_EXT_ITEM` ($68) counts inventory **and** equipment of all 16 records. | Low | Event scripts that must remove an equipped item should use `$8D` first. |
| R4 | `GIVE_EXT_ITEM` ($66) with a full inventory (no stack of that id, no empty slot) gives nothing, silently; stacks cap at 99. | Low | Same as vanilla `$80` behaviour with a full inventory. |
| R5 | In battle, the hand holding an extended item cannot be **replaced** from the inventory (refused like a vanilla refusal). R-hand ↔ L-hand exchange is allowed (bits follow). | Low | The battle write-back stores low bytes only; the guard prevents truncation (B3, B3b). |
| R6 | Battle end: a vanilla item that the battle placed at an extended-backed position is re-homed (merge, else first free vanilla slot). With all 256 slots occupied it would be dropped. | Very low | Needs 256 distinct occupied slots. |
| R7 | Dialogue text cannot print extended item names (the text item-name command takes a 1-byte id). | Low | Use literal text in dialogue for extended items. |
| R8 | Extended **weapons/shields** must not be equippable by Gau or Umaro. | Rule | Rage (C2:0610) overwrites both hand ids; the builder refuses such definitions (selftest). |
| R9 | Item-list text colour of an extended item is computed from its alias's properties (always grey: aliases `$00-$3F` are weapons). | None today | Extended consumables are out of scope; they would need a hook at C3:8056. |
| R10 | **Inherited Rev 1 behaviour:** in battle, a hand-first exchange followed by leaving the Item menu with B writes the new hand to `$161F` but restores the battle list (net effect at battle end: the old hand item disappears, the new one is duplicated). | Vanilla bug, unchanged | Differential B3c: v0.7.1 and the clean Rev 1 ROM end with identical bytes; extended slots are preserved. Not fixed (vanilla behaviour must stay unchanged). |
| R11 | Extended spear flag (Jump ×2): Sandpiercer `$104` / Gale Lance `$10B` now runtime-tested in the emulator (J1: every Jump frame equals the template spear in the same battle). Damage ×2 itself is not measured numerically. | Low | Statically wired (I531/I532, `XExtFlags` bit 1, selftest 44). |
| R12 | Battle-start timing: the extra C2 work during battle setup (UpdateEquip / hands / inventory post-pass, all with zero-bitmap fast paths) makes **26 of 576** vanilla formations reach the same battle screen **one frame later** than v0.6.0 (screens identical when sampled one frame later; engine data 576/576 identical). Data/graphics are unaffected; RNG-driven ATB order can differ from v0.6.0 for the same input timing. | Info | Measured in `REGRESSION_REPORT_v0.7.1.md` §3. Only removing all C2 hooks restores the old frame. |
| R13 | `$1E3E` / `$1E3F` (transient scratch) are saved with whatever value they hold. | None | Always written before read; never read across a load. |
| R14 | Seven relics ship with their **BAL-18 stat fallback** (no new relic ASM in v0.8): Runic Crest, Maduin's Locket, Doma Crest, Darill's Coin, Beastheart, Engineer's Badge, Master's Cord. The deferred effects are listed in `FALLBACK_EFFECTS_v0.8.md`. | Info (by design) | Identity, users, slot and source unchanged; a later module adds the effect. |
| R15 | Emulator evidence is snes9x (stable-retro) only. | Info | v0.8 user runtime QA PASS on the user's emulator. |
| R16 | **Event `$80` (give item) timing:** the find-same-item loop reads each slot through the extended-slot mask (I210), so a give that scans the whole inventory takes up to one frame longer than in Rev 1 (measured: four new items, 9 frames instead of 5). Items, quantities and order are identical. Because the game clock keeps running, the frame count at later RNG seeds (e.g. a battle's `$BE` seed from `$021E`) can differ from Rev 1 for the same button timing, the same way as player timing does. | Info | Timing only; any frame-exact comparison with Rev 1 must align the clock (`tools/emu_colosseum.py` does). |
| R17 | QA harness "Colosseum (full battle)" calls the vanilla receptionist branch CB:78D9. With event switch `$1EF` set (World of Ruin, Shadow-at-the-Colosseum state) that branch runs the Shadow scene, which expects the Colosseum map. | QA only | `$1EF` is 0 in every New Game; the harness is item-tech only and documented for New Game use. |
| R18 | **Vanilla (Rev 1):** the Colosseum looks up its fighter by actor id = character record number (`$0208` → `$3ED8`, C2:2F80). A temporary character in record 14/15 (e.g. Wedge actor $20, Vicks actor $21 in the opening) gets no sprite, no name and no record pointer: the fighter is invisible. | Vanilla, unchanged | Cannot happen in the real Colosseum (only permanent characters 0-13). QA uses a normalized party (v0.7.3). |
| R19 | **Vanilla (Rev 1):** a Colosseum fighter with Magitek status turns on battle Magitek mode (`$7E64BA`), so an extra armor-like sprite is drawn. | Vanilla, unchanged | Not reachable in the real Colosseum. The QA menu clears Terra's Magitek for the fight and restores it afterwards. |
| R20 | QA menu `Fight: Terra/Locke/Celes/Edgar` initializes Locke/Celes/Edgar with event `$40` (vanilla CharProp stats/equipment, average level) and leaves those records initialized (not in the party) after the fight. | QA only | Records are re-initialized by the vanilla story events (`char_prop`) when these characters join. The available-characters mask `$1EDE` (used for the average level) is not changed. Item-tech QA ROM only. |
| R21 | **12-character display names.** The game's item name field is icon + 12 characters (vanilla max). 18 locked names are longer and are shown in a deliberate 12-char form (`TemperedEdge`, `ImperialSabr`, `ImperialMntl`, `MagisterRobe`, `FalconJacket`, `ChildsRibbon`, `Eng. Goggles`, `Concord Shld`, `MaduinLocket`, `KeepsakeRing`, `Darill'sCoin`, `MemorialBand`, `PaintersLens`, `Eng. Badge`, `Master'sCord`, `LegacyofMagi`, `Darill'sDirk`, `ConcordBrush`). The full locked name stays in the source (`locked_name`), the master table and the description where useful. | Info (documented) | Widening the name field touches every menu/battle list renderer (C1/C3) - out of scope. No locked name was changed in the source. |
| R22 | **Acquisition is bound, not placed.** Every item has one one-time binding (`reward_id`, `future_event_symbol`, conditions), but the story events / maps that give them are not implemented yet; 11 armor/helmet/shield items have `source_type = arc_reward_tbd` (the locked Armor sheet names no source). | Info | QA grants the items through the QA menu only. Future events must use `give_ext_item` / `has_ext_item` (validator: unique reward ids / symbols). |
| R23 | Smith GP costs (18000 / 20000 / 24000) are **derived** (not locked) and the smith quest prerequisites are placeholders. | Info | Documented in the master table `derived` field; creative review can change them without engine work. |
| R24 | QA `Remove all 39` takes up to 10 of each id from the inventory; equipped items are not taken (R3). | QA only | Use Equip → Empty first. |
| R25 | **Event `$40` (char_prop) re-initializes a character and drops its equipment** (vanilla behaviour; the v0.7.1 hook I216 also clears that record's extended bits so no stale bit survives). A future story event that re-runs `$40` on a character wearing signature gear would lose the gear. | Medium (future content) | Story scripts must unequip / re-give signature gear around `$40`, or not re-run `$40` on joined characters. QA presets initialize each character once only (`QA_V08_PARTY_READY`). |
| R26 | Raider Knife's steal-on-hit uses the vanilla ThiefKnife special: it steals the monster's vanilla steal items only (1-byte ids). Signature items can never be stolen / dropped / metamorphed / thrown / wagered. | By design (Option C) | Emulator X1-X3, I1; static exclusion list in the acquisition map. |
| R27 | Extended equipment has no MERIT-award flag (`$8000` in the equip word): the Merit Award does not open signature gear to other characters. | By design | Signature identity (locked users) is kept; validator checks users. |
| R28 | Leaving the Relic menu after equipping Genji Glove / Gauntlet re-evaluates the hands (vanilla): the hand items can move or change. Signature items keep their 9-bit ids (emulator G1/H1). | Vanilla behaviour | User guide step: re-check the hands after changing these relics. |
| R29 | **Test rule:** a battle must never be started from an event script injected into WRAM (battle RAM overwrites it). All emulator battles use ROM labels (`QaTestBtl8`, `QaBossBtl8`). | Test tooling | Earlier bisects that injected battles are invalid and not reported. |
| R30 | QA party presets: Terra always leads; the first preset initializes all 13 other permanent characters once (event `$40`, vanilla CharProp + average level) and they stay initialized. `Opening party` restores Terra/Wedge/Vicks + Magitek. | QA only | Item-tech QA ROM only; production unaffected. |
| R31 | Balance: locked values dominate some endgame vanilla options (e.g. Doma Edge 222 > Strato for Cyan, Royal Gear / Imperial Mantle / Magister Robe > Crystal Mail / Diamond Vest). None beats Illumina / Ragnarok / Paladin Shld / Minerva in every respect; Optimum keeps Illumina/Ragnarok (stress L2). | Design review | `EQUIPMENT_BALANCE_AUDIT_v0.8.md` lists every case for creative review; no locked value changed. |
| R32 | **Engine fix (v0.8):** the accepted v0.7.1/v0.7.2 C3 hooks could leave the extended-id high bit in the B accumulator; `SortValidEquip` used it in a 16-bit `TAY`, so Equip-list order and Optimum ranking could be wrong with extended items (read-only; no loss / duplication). Fixed in `asm/item_v08` (B := 0 exits); the frozen v0.7.x ROMs keep the old engine byte-exact (they contain no production items). | Fixed | `ENGINE_FIX_v0.8_B_ACCUMULATOR.md`; static audit 1 finding (unreachable); emulator stress L2/L3; selftest 43b/43d. |

Emulator evidence is snes9x (stable-retro); **USER RUNTIME PASS** (v0.8 consolidated QA).
