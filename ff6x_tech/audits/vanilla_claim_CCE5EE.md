# Vanilla-space claim: CC:E5EE–CC:E5F2 (EVTEST_NPC_TRAMPOLINE)

**Used by:** `evtest` target only (T201). **Size used:** 5 of 18 padding bytes.
**PC:** `0x0CE5EE–0x0CE5F2` · **SNES:** `CC:E5EE–CC:E5F2`
**Original bytes:** `FF FF FF FF FF` · **New bytes:** `B2 00 00 27 FE`

## Why vanilla space is needed at all
NPC event pointers are 18-bit (`NPCProp` bytes 0–2, `and #%11` on the high byte,
then `adc #$CA`) → reachable range is **CA:0000–CD:FFFF** only
(C0 field code, obj.asm NPC loader / activation). F0–FF cannot be targeted
directly by an NPC, so a 5-byte stub inside CA–CD is the smallest bridge.

## Safety evidence
1. **Disassembly layout.** In the everything8215/ff6 disassembly, segment
   `event_script` is `fixed_block $02E600` (CA:0000–CC:E5FF). The last assembled
   instruction is `GameOver`'s `return` at **CC:E5ED**; CC:E5EE–CC:E5FF is
   linker padding generated by `end_fixed_block` (18 × `FF`).
2. **Byte-identical reassembly.** The disassembly built with `ROM_VERSION=1`
   reproduces the Rev 1 event bank (CA–CC) byte-for-byte, so the padding
   is not hidden data.
3. **No symbol** in the debug file (`ff6-en.dbg`) resolves into CC:E5EE–CC:E5FF.
4. **No pointer into the range** (negative scans of the clean ROM):
   - 2,193 NPC records (all maps): 0 hits.
   - 1,164 event triggers (24-bit pointers): 0 hits.
   - Whole-ROM 3-byte pattern scan for offsets `0x02E5EE–0x02E5FF`: 7 coincidental
     hits, none inside event-related data (PC 0x04BCD4, 0x19309C, 0x19ACBD,
     0x242783, 0x271BF2, 0x2748D1, 0x2FEC39 — font/graphics/animation banks).
5. **Neighbour check.** CC:E600 (`DlgBankInc`, word 0x0626) is untouched;
   the claim ends at CC:E5F2.

## Residual risk
Low. Data/code that computes an event address arithmetically into this padding
would have to exist without a label; none is known. The claim is declared in
`data/allocations.json → vanilla_space_claims` and the builder refuses any write
outside it. Production code should prefer this padding only for small bridges.
