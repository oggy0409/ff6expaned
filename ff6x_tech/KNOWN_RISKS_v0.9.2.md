## New rows

| # | Risk | Severity | Mitigation / evidence |
|---|---|---|---|
| R45 | **Save compatibility v0.9 → v0.9.1 / v0.9.2** depends on `$1E23-$1E26` (free saved RAM in v0.9, now the transient item-action context) being cleared at load. | Low | ClrTrans clears them at New Game / load; emulator `save_compat_v092` C1 (inventory, equipment of all 16 records, extended bitmap, rare block, GP identical; transient bytes 0) and C2 (a carried-over Gaia Tonic heals exactly 1500). |
| R46 | **Fixed amounts bypass the formula.** Gaia Tonic 1500, Iron Ration 600 and Magitek Cell 800 ignore level, Magic, M.Def, row and variance (items already have no variance in Rev 1). | R49 | **Vanish removal by an item.** The vanilla Item command clears zb3 bit 7, which makes MagicStatusEffect cancel any Vanish removal. Beacon Flare removes Vanish but **not** Image (D-17). | Low | Emulator cb91 (Null Dust exact Dispel set; Beacon: Vanish removed, Image kept). |

| R67 | **Battle timing (lag frame) with extended weapons** - pre-existing since the v0.8 extended-weapon hooks, made visible by the v0.9.2 regression. The extended-weapon paths cost a few more CPU cycles than a vanilla weapon. When the character's action is processed while a monster animation is running, the extended run can take one more frame (lag frame): the overlapping monster animation is then drawn one frame apart from the template-weapon run and the following ATB values are one tick apart. The weapon / Jump / Offering animations themselves are identical, damage and HP results are identical. | Info (timing only) | `tools/emu_timing_probe_v092.py` (same battle, extended vs template weapon, 16 start phases, guards kept alive): **frozen v0.9 ROM** Offering diverges at 2 of 16 phases; v0.9.2 ROM Jump 3 / 16, Offering 16 / 16 (that battle state has a guard action overlapping at every phase); without the guard POKE (8 phases x 2 weapons): v0.9 16 / 16 identical, v0.9.2 15 / 16 (Jump, one phase, divergence after the landing). With the monster ATB held (no overlapping action) the v0.9.2 Offering case is frame-identical (0 / 900 frames differ). `tools/emu_timing_ramdiff_v092.py`: the first differing RAM after the hand bytes is the weapon animation number (`$B7` = `$C4` / `$C6` vs the template's), then stack / DP temporaries, then ATB / timer bytes one tick apart. `emu_equip_battle_v08` J1 / O1 now hold the monsters' ATB (POKE, identical in both runs) and compare every frame strictly. Like player input timing (R12 / R16), ATB order can differ by a frame; nothing else. |
