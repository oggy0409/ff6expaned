# TECH v0.5 — known risks / open items

| # | Risk | Severity | Mitigation / status |
|---|---|---|---|
| R1 | Consumer completeness relies on the symbolic Rev 1 disassembly (.dbg cross-reference). A table access not expressed through a symbol would be missed. | Medium | 71 consumers asserted byte-exact; **differential emulator test vanilla vs production v0.5 over all 576 vanilla formations: battle-engine data identical 576/576**; QA battle + Steal/Sketch/Control poke test; user QA. |
| R2 | Vanilla monster/formation tables stay in ROM as dead data; editors writing the vanilla addresses have no effect. | Medium (tooling) | Builder + `monsters/`, `formations/` sources are the only authoring path. |
| R3 | Formations ≥ $200 award **0 magic points** (engine bound C2:5D97 `CPX #$0200`). Every new formation ($240+) is affected. | Medium (design) | Reported, not changed (v0.5 scope). Needs a small extension before production random encounters with Espers equipped. Event/boss battles may be acceptable without AP — design decision. |
| R4 | New custom palettes / graphics tile data are not available yet (vanilla palette table and graphics window only). | Medium (assets) | QA monsters reuse vanilla graphics + palettes. Graphics/palette allocation is a separate architecture step before final art. |
| R5 | Colosseum detection changed from "battle ≥ $23E" to "$23E ≤ battle < $240" (N303). Vanilla never uses battles ≥ $240, so vanilla behaviour is unchanged. | Low | Differential test includes $23E/$23F (identical). Colosseum not runtime-tested by the user yet (late game). |
| R6 | Graphics slot remap: monsters $180–$1FE use gfx-prop slots $1A0–$21E. Any future code that indexes MonsterGfxProp directly by monster id (instead of through the router) would read the wrong slot. | Low | All 15 gfx-prop consumers audited: monster loader + Sketch use the router; summon/Imp/colosseum menu use vanilla ids < $180. |
| R7 | Added cycles: JSL + ~10 instructions per monster at battle load and per Sketch. Observed: battle fade-in lags **1 frame** in 2 of 576 formations ($03D, $10F) vs vanilla. | Low (cosmetic timing) | Engine data identical; screens identical in 574/576 at the sample frame; the 2 differ only by the 1-frame phase. |
| R8 | TESTMOB A AI deviates from the first plan (Fire → Mute): monster Fire hit every opening party member for ~30 HP and wiped the QA party. | QA-only | Documented in `monsters/tech_0180/ai.txt`. Mute (A) / Slow (B) are distinct and observable. |
| R9 | Steal/Sketch/Control cannot be used by the opening Magitek party; they were verified only with a RAM poke (Terra's status/commands) in the emulator. | QA-only | User marks them NOT TESTED unless tested another way. |
| R10 | QA battle is in the opening Magitek sequence, Wait battle mode: buffered inputs can open the empty opening **Item** list (blank window) where time stops — vanilla behaviour, B closes it. | QA-only | Noted in the user guide. |
| R11 | Rage expansion not implemented (policy: new monsters excluded). | Info | Report in MONSTER_DEPENDENCY_AUDIT_v0.5.md §6; needs approval. |
| R12 | Event battle groups $9A–$FF are unreferenced in the audit; QA uses $FE (monster-tech only). Production use of further groups must be re-audited per group. | Low | Builder claim `QA_EVENT_BATTLE_GROUP_FE` only in monster-tech. |
| R13 | Monster records for new IDs are built from a vanilla base record (`stats.json` → `base_vanilla_monster`); fields not listed (elements, status immunities, special-attack flags, metamorph id…) are inherited from the base. | Info | Intended for QA; production monsters should list every field explicitly (a later source-format revision). |
| R14 | KNOWN_QA_ISSUE_v0.3.1 still applies: QA tile is in the opening Magitek sequence → field sprite after Continue is the walking sprite. | QA-only | Do not use for field-sprite persistence tests. |
